# Agent 基建平台 · 前端框架原型

本阶段提供全局导航、设计规范样板页、4 个 Agent 的演示数据，以及「内部制度问答助手」的完整主路径：新建、配置、调试、评测、发布、监控和回退。上线门槛、灰度与 AB、回退、Trace、护栏、成本等生产能力直接融入各页面（见下文），全部为前端交互 + mock 数据。

## 信息架构（两个轴）

- **一级导航（横轴 · 平台共享）**：工作台（待办 + Agent 目录）· 资产中心（下挂六个常驻二级目录：知识库 `#/assets/knowledge`、数据库 `databases`、工具 `tools`、评测集 `evalsets`、模型 `models`、Prompt 模板 `prompts`）· 监控与成本（`#/operations`）· 治理（`#/governance`）· 模板广场（二期，置灰）。
- **知识库**：页内左侧是知识库目录（团队 → 知识库 → 版本，可搜索），右侧是选中版本的条目、生效期和引用情况；窄于 1024 时目录收成下拉选择。
- **Agent 内（纵轴 · 生产闭环）**：构建（发布过后叫「构建与调优」）→ 评测 → 发布与实验 → 观测 → ↺ 下一轮，外加设置。观测包含「监控」（`/monitor`）和「Trace 与 bad case」（`/trace`）两个标签页；`/agents/:id/observe` 会跳到监控。
- **调优闭环**：调优不单独成页，而是贯穿迭代：观测 / 评测发现问题 → 纳入本轮优化 → 回到构建与调优修改 → 调试 → 评测核对 → 灰度验证 → 继续观测。一轮优化 = 一个候选版本 + 一组要解决的问题。发布过的 Agent 第一步显示为「构建与调优」（从没发布过的仍叫「构建」）；「观测」后面的「↺ 下一轮」是按钮，打开右侧抽屉：上面是本轮进度（① 改配置 ② 调试 ③ 评测核对 ④ 灰度验证）和已纳入的问题，灰度中版本上的上一轮问题单独列为「验证中」；下面是待处理问题队列（告警、门槛未过、AB 变差排在前面，bad case 按影响度排序），每行可直接「纳入本轮」。导航徽标显示「本轮 v22 · N 个问题」「v22 验证中 · N 个问题」或「待处理 N」。告警、AB 报告、评测门槛处的「纳入本轮优化」打开预填表单（问题来源、调优对象、目标指标、验证方式）后进入构建与调优。构建页三栏上方显示「本轮优化目标」：本轮进度、每个调优对象的建议动作、目标列表（可展开 / 移出本轮），调优对象对应的模块高亮，调试台多一组「本轮问题」（bad case 原话，调优对象改过就按期望回答、没改就复现问题）；评测页核对目标是否达成（bad case 必须真的在这个版本的回归集评测里，评测后才加入的要重新运行）；发布页生产就绪检查多一项「本轮优化目标已验证」（只提示，不阻断）。逻辑在 `src/core/rules/optimization.ts`、`src/core/rules/problems.ts`，界面在 `src/features/optimize/`。
- **bad case 工作台**（Trace 页，排在 Trace 树上方）：一行 = 一类问题（同类合并「×N 条相似」），每个示例 Agent 8 类；影响度 = 相似条数 × 来源权重（申诉 3 / 用户反馈 2 / 抽检 1）× 是否出在服务中的版本（×1.5），已修复、已忽略沉到最后。状态标签：待归因 / 已归因 / 已纳入本轮 / 验证中 / 已修复 / 已忽略；筛选：时间、问题环节（含平台建议）、来源、版本、排序。点行内展开（不用抽屉，再点收起），默认展开影响最大的待处理问题：原始样本（用户原话 / Agent 输出 / 备注）、期望输出或判定标准（预填、失焦自动保存）、Trace 摘要（标出异常步骤，下方 Trace 树同步切换）、平台建议归因及依据、人工确认问题环节；操作：主按钮「纳入本轮优化」（按确认的归因或平台建议设调优对象，自动加入 bad case 回归集，留在当前页）、「加入回归集」/「移出回归集」、「更多」里的「线上干预（临时止血）」（只对出在当前线上版本的问题提供；批量模式只能用拦截规则）和「忽略」（选原因，同时移出回归集）。可勾选后批量纳入本轮、加入回归集、忽略。上一轮纳入过但版本被回退、或上线了却没在回归集上验证的问题回到待处理，并提示上一轮的结果。
- **资产的详情、新建、修改**：点资产名称打开右侧详情抽屉，页头按钮打开新建抽屉。已发布的版本可能被 Agent 版本快照锁定，所以「修改」先选方式——**发布新版本**（改全部内容，旧版本不变；工具只对本团队可见时保存即发布、对全公司开放要审核，模型要审核，可在详情里「模拟审核通过」或「撤回」；数据库、评测集、Prompt 模板保存即发布）或**修改当前版本**（没被引用时改全部内容；被引用时只能改负责人、描述等基本信息，行为字段锁定并说明原因）。工具、模型提交前必须先测试调用 / 连通性测试；新建或追加的评测集样本会出现在对应 Agent 的评测页。知识库的修改仍走「基于 vX 新建版本」的草稿流程。
- **面包屑**从当前页面所属的一级目录开始：Agent 页面为「Agent 目录 > Agent 名称 > 步骤」，资产中心为「资产中心 > 二级目录」，其余只显示页面名。
- 旧地址保留跳转：`#/library`、`#/assets` → 资产中心 · 知识库，`#/assets?tab=xx` → 对应二级目录，`#/evaluation` → 资产中心 · 评测集，`#/settings` → 治理。
- 详细说明见 `Files/PROJECT_CONTEXT.md`「信息架构：两个轴」。

在本目录运行 `npm install`、`npm run build`。构建完成后，直接打开 `dist/index.html`；页面通过 Hash 路由切换，刷新不会请求服务端。`npm run dev` 可用于本地开发。

## 代码结构

```
src/
├─ data/          mock 数据。唯一入口 data/index.ts；base/ 按功能拆分，scenarios/ 按剧本 A / B / C 拆分
├─ core/          与界面无关的状态、规则和取数
│  ├─ store/      演示状态（DemoProvider）与按领域分组的操作（actions/：版本、发布、运营配置、知识库、剧本）
│  ├─ rules/      版本与线上指向、生命周期、上线门槛与就绪检查、演示时钟、diff
│  ├─ data-access/scenarioData.ts   统一取数，演示剧本在这里替换数据
│  └─ hooks/
├─ shared/        跨页面复用：components/（按钮、徽章、卡片、能力卡片、开关、告警条…）和 styles/（设计变量、基础样式、通用组件样式）
├─ features/      一个功能一个文件夹：页面、专用组件、专用样式
│  └─ shell / directory / create / build / evaluation / release / monitor / trace / settings / library（资产中心）/ operations（监控与成本）/ governance（治理）/ playbook / design-system / placeholder
└─ types/domain.ts
```

- 依赖方向：features → shared → core → data → types，只允许从左往右引用；功能之间尽量不互相引用，例外是公共外壳 `features/shell` 和剧本锁定 `features/playbook/playbooks`。
- 样式：`main.tsx` 先引入 `shared/styles/base.css`、`components.css`，各页面在自己的文件里引入本页样式，打包后仍内联进单个 HTML。只引用 `shared/styles/tokens.ts` 的设计变量。

## 检查脚本

首次使用前运行 `npx playwright install chromium`。脚本直接打开 `dist/index.html`，先 `npm run build`。

- `npm run smoke`：三条演示剧本从头走到尾，加上已修复问题的回归检查。
- `npm run snapshot`：记录基准截图（主要页面 × 1440 / 390 宽，另含弹窗、剧本中途等交互状态）。
- `npm run snapshot:compare`：重新截图并与基准逐像素比对，列出有差异的截图。改样式前先记录基准，改完再比对。截图保存在 `scripts/.snapshots/`（不进仓库）。

## 版本模型

- 每个版本都是不可修改的快照（主模型与备用模型、Prompt、步骤、工具、知识版本、记忆、输出格式）。只有候选版本（草稿 / 待发布）可以编辑。
- 线上、历史版本只读；要修改时在构建页「基于 vX 新建草稿」。
- 构建页的修改先自动保存为工作草稿（`version.draft`，600ms 防抖，不推进演示时钟、不改快照）；调试直接调当前草稿，不需要先保存。点「保存为候选版本」才把草稿写入快照：配置有变化时评测结果失效，调试结果只有在调试的正是这份草稿时才保留。
- 候选版本需要：已保存为候选版本 + 已调试 + 至少一个评测集，才能发布。评测运行的是已保存的快照，构建页有未保存草稿时评测页会提示。依赖一键升级、剧本的「代我修改 / 代我修正」直接写入快照（草稿一并清掉），调试和评测仍需手动运行。
- 发布和回退都只改变生产环境的「线上指向」。只有曾经上线过的版本可以回退，草稿、待发布和灰度中的版本不能回退。
- 同一时间只允许一个实验：有灰度或影子运行时，不能发布新版本，也不能从版本历史回退，需先放量完成或回退实验。
- 所有操作时间使用演示时钟：从 2026-09-29 12:00 开始，每次操作前进 1 分钟；读取存档时对齐到最晚的操作时间。知识条目的生效 / 失效状态也按演示时钟计算。
- 相关逻辑在 `src/core/rules/versions.ts`、`src/core/rules/clock.ts` 和 `src/core/store/actions/`。

## 数据与存储

页面数据为 mock，放在 `src/data/`，4 个 Agent 各有自己的配置、调试预设、评测集和监控数据；页面只从 `src/data/index.ts` 引用。演示进度保存在浏览器存储中（键名 `agent-platform-demo-v9`）。数据结构变化时要同步提升 `src/core/store/storage.ts` 里的版本号，旧存档会被自动丢弃。页面出错时只替换内容区，可点「重置演示」恢复。Google Fonts 无法访问时会使用系统字体。

## 生产能力

- 生产骨架是产品设计时考虑的点，直接融入页面流程；界面上不显示骨架编号、「生产骨架」区块或「主角」标签，也没有能力视图切换。每个功能只标 MVP / 二期。
- 能力卡片用 `src/shared/components/Capability.tsx` 的 `Capability` 包裹：自带 MVP / 二期徽章；二期整块置灰不可点。
- 各页能力：构建页（三栏：Prompt 含「优化」建议 diff 与「套用模板」/ 能力配置按千帆的能力扩展分组：模型（主 / 备用模型、最大思考次数、参考对话轮数）· 技能（工具、执行步骤）· 知识（知识库 + 检索设置、数据库）· 记忆（记忆变量、记忆表、记忆片段）· 对话（开场白、推荐问、追问）· 输出与安全（输出格式、护栏）；默认只显示已添加的内容，小模块右上角 ＋ 打开添加弹窗，从资产中心搜索添加，或直接上传 / 创建（同时入库）；同一个工具只挂一个版本，知识库、数据库各最多 1 个；批量模式下记忆和对话整组停用 / 多轮调试对话吸顶，显示开场白、推荐问和追问建议；依赖有上游更新时在三栏上方提示；底部「版本快照与对比」默认折叠，含依赖锁定和版本 diff）、评测页（隔离环境、上线门槛、批量评测）、发布与实验页（生产就绪检查、发布策略、流量指向、AB 报告、放量与回退、接入方式：app_id、调用地址、按线上指向 / 指定版本调用的示例代码、调用方登记与 QPS 配额）、观测页（监控、Trace 与 bad case 两个标签页；bad case 可生成线上干预：标准答案 / 拦截规则，最长 7 天，修复版本在 bad case 回归集上评测通过并成为线上版本后自动失效，创建 / 撤销 / 失效都写入治理 · 最近操作）、Agent 设置页（运行保障、告警、护栏、成本）；平台级：资产中心（知识、数据库、工具、评测集、模型、Prompt 模板的版本与引用）、监控与成本（跨 Agent 运行表、团队预算、限流与降级一览）、治理（角色与授权、护栏覆盖、审计日志）。
- 门槛与就绪检查逻辑在 `src/core/rules/gate.ts`；灰度、放量、回退操作在 `src/core/store/actions/releaseActions.ts`；相关 mock 按功能放在 `src/data/base/`。
- 推荐演示路径：内部制度问答助手 v4 构建（改草稿、直接调试）→ 保存为候选版本 → 评测 → 发布页看就绪检查（缺告警与审批）→ 设置页开启告警 → 提交并模拟审批 → 比例灰度发布 → 放量 → 回退到 v3（显示耗时）。社区穿搭灵感 Agent 可直接演示「回退到 v12」，生态守护 Agent v8 演示门槛阻断。

## 演示剧本

- **自由浏览与剧本模式分开**：从工作台 Agent 目录点进任何 Agent 都是自由浏览，剧本暂停（不显示浮层、不锁定按钮，状态里记为 `playbook.paused`）；只有点「开始剧本 / 继续剧本」才进入剧本模式。退出剧本有两种方式：浮层里的「退出剧本」，或右上角「重置演示」后从 Agent 目录进入；开始剧本的确认框和浮层里都有这条提示。

- 工作台 Agent 目录下方有三条可点击的剧本：A 社区穿搭灵感 Agent（快）、B 生态守护 Agent（准）、C 电商售后答疑 Agent（稳）。三条结构一致，都从新建候选版本开始，走完「构建 → 调试 → 评测 → 发布 → 上线后」（C 先用 4 步从 bad case 找到起因），浮层里每一步都标出所属阶段。点「开始剧本」后，对应 Agent 换成剧本的初始数据（其它 Agent 不变），并跳到第一步。
- 右下角「演示步骤」浮层显示第几步、下一步点哪里（页面目标元素会虚线高亮）。浮层只在当前步骤所在页面自动展开，其它页面显示胶囊，点胶囊直接前往该步骤；✕ 只收起不退出，收起状态换页、刷新后保持，「退出剧本」在浮层底部。完成页面上的真实操作后自动进入下一步（收起时也照常推进）；A 改推荐策略、B 改 Prompt、C 填知识生效时间三步提供「代我修改 / 代我修正 / 代我填写」。剧本 A 从线上 v12 开始、没有 v13；告警和 v13 的 Trace 在 v13 开始灰度后才出现，时间按实际灰度时间计算。
- 页面和组件不变，只换数据：剧本 Agent 使用 `pa / pb / pc` 数据配置，页面统一经 `src/core/data-access/scenarioData.ts` 取数；剧本步骤定义在 `src/features/playbook/playbooks.ts`，浮层与入口在 `src/features/playbook/`，剧本 mock 在 `src/data/scenarios/`。
- 顺带补齐的通用能力：依赖提醒可一键「创建候选版本并升级依赖」；知识库可「基于 vX 新建版本」并编辑每条知识的生效 / 失效时间；影子运行只需门槛、护栏、负责人三项，全量发布前再审批。
- 剧本进行中会锁定容易走偏的入口（构建页「新建草稿」、发布策略、知识库「放弃草稿」），按钮下方说明原因。开始剧本前页内确认会覆盖该 Agent 的演示进度；退出剧本时可选择保留数据或恢复原始数据。
- 存档 schema 为 v9（键名 `agent-platform-demo-v9`；v9 加入优化目标 `ops.goals`，v8 加入数据库资产和版本配置里的最大思考次数、检索设置、数据库、记忆、对话体验，旧存档会自动作废）。「重置演示」会同时清除剧本进度。所有数字均为演示数据。
