# 项目上下文（每次对话都附上）

## 产品
公司级 Agent 基建平台，内部平台，面向业务团队。
一句话定位：外部平台解决「怎么把 Agent 做出来」，我们解决「公司内任何团队做出来的 Agent，
怎样用同一套标准安全上线、持续变好，并把能力沉淀给下一个团队」。
纯前端原型，所有数据为 mock，每个页面右上角标注「演示数据」。

## 两层结构
- 平台基础能力（任何 Agent 都有）：构建、评测、发布、运行、观测、治理
- 生产骨架（10 项，从业务中抽象）：
  ① 变更与版本管理 ② 上线前评测验证 ③ 受控发布 ④ AB 实验与效果度量
  ⑤ 回退与下线 ⑥ bad case 归因与优化 ⑦ 运行保障 ⑧ 可观测与可追溯
  ⑨ 输出安全护栏 ⑩ 合规与成本

## 信息架构：两个轴（2026-09-30 定稿）
- 核心区别：外部构建平台（如百度千帆）以「资源」为中心组织导航；本平台以「Agent 版本 + 线上指向」为中心，
  按一个 Agent 怎样上线、怎样变好来组织。
- 纵轴 · 每个 Agent 的生产闭环（差异化主要在这里）：进入某个 Agent 后按步骤切换
  构建 → 评测 → 发布与实验 → 观测（「监控」「Trace 与 bad case」两个标签页）→ bad case 回流评测集，开始下一轮；
  另有「设置」（运行策略、护栏、成本），不计入步骤编号。
  - 构建页（2026-09-30 定稿）：顶部 Agent 信息和生命周期导航不变；下方三栏 30 : 38 : 32——左「角色指令」Prompt（优化建议以 diff 呈现、采纳后写入草稿；
    套用资产中心的 Prompt 模板，复制不引用）/ 中「能力配置」参照千帆能力扩展分组：模型（主 / 备用、最大思考次数、参考对话轮数）· 技能（工具、执行步骤）
    · 知识（知识库 + 召回条数 / 阈值、数据库）· 记忆（记忆变量、记忆表、记忆片段）· 对话（开场白、推荐问、追问）· 输出与安全（输出格式、护栏只读）。
    默认只显示已添加的内容；小模块右上角 ＋ 打开添加弹窗（搜索资产中心，或上传 / 创建后同时入库）；同一个工具只挂一个版本（在卡片上切换），
    知识库、数据库各最多 1 个；批量模式下记忆和对话整组停用。声音形象、背景图片、专业词库、对话卡片不做。
    / 右「预览与调试」多轮对话，显示开场白、推荐问，开启追问时回答后给追问建议；桌面端吸顶，窄屏收成抽屉。
    草稿自动保存、调试无需保存；「保存为候选版本」写入快照。依赖有上游更新时在三栏上方提示并可一键升级；「版本快照与对比」（依赖锁定 + 版本 diff）放在三栏下方、默认折叠。
    1280–1439px 左、中两栏上下排列，调试栏仍在右侧；< 1280px 调试栏变成抽屉。
  - 发布与实验页底部「接入方式」：app_id、调用地址、默认按线上指向调用（发布和回退对调用方透明），回放 / 对账 / 申诉复核可锁定版本；
    调用方登记（服务名、场景、负责人、QPS 配额、跟随线上或锁定版本），配额合计不能超过设置页限流；锁定的版本不再是线上时提示。
  - 观测 · Trace 与 bad case 的「线上干预」：由 bad case 生成（标准答案 / 拦截规则），必须关联 bad case、最长 7 天；
    关联 bad case 已加入回归集、且修复版本在回归集上评测通过并成为线上版本后自动失效；创建 / 撤销 / 失效写入治理 · 最近操作。监控页顶部提示生效中的干预。
- 横轴 · 平台共享（跨 Agent）：一级导航
  - 工作台：待办（待审批、灰度 / 影子运行中、候选版本待发布）+ Agent 目录 + 演示剧本入口。
    Agent 目录列：Agent（名称，下方为团队 · 负责人 · 执行模式；原型级别在名字旁加标签）· 线上版本 · 进行中（灰度 / 影子 / 待审批 / 候选）
    · 运行健康（告警 + 在线看 P95、批量看错误率）· 业务核心指标（近 7 日线上信号，一个看结果、一个看质量或风险）· 本月成本（预算使用率）
  - 资产中心：左侧导航下常驻六个二级目录——知识库、数据库、工具、评测集、模型、Prompt 模板（地址 #/assets/:tab），都带版本，登记一次、任何 Agent 引用。
    知识库页内有一栏知识库目录（团队 → 知识库 → 版本，可搜索），不覆盖左侧一级导航；窄屏时收成下拉选择。
    每个二级目录页头有新建按钮（新建知识库 / 创建数据库 / 新建工具 / 新建评测集 / 接入新模型 / 新建 Prompt 模板），点资产名称打开右侧详情抽屉；
    列表：工具 = 工具 · 接口 · 负责人 · 在用版本 · 最新版本 · 被引用；模型 = 能力 · 上下文 · 单价 · 首字 P95 · 数据等级 · 在用 Agent；
    Prompt 模板 = 模板 · 版本 · 结构 · 沉淀自 / 负责人（类型、变量、正文放在详情和新建里）；
    数据库 = 数据库 · 来源（上传表格 / 连接业务库只读视图）· 表 / 行数 · 数据等级 · 负责人 · 被引用
  - 资产的修改规则：已发布版本可能被 Agent 版本快照锁定，「修改」先选方式——发布新版本（改全部内容，旧版本不变；模型需审核；工具只对本团队可见时保存即发布、对全公司开放需审核；数据库、评测集、Prompt 模板保存即发布）
    或修改当前版本（未被引用时改全部内容；被引用时只能改负责人、描述等基本信息，行为字段锁定并说明原因）。
    工具提交前必须测试调用，模型必须连通性测试；外部模型数据等级固定为「仅内部数据 · 需审批」
  - 监控与成本：全部 Agent 的运行状况、告警、团队预算与配额、限流与降级一览
  - 治理：三种角色（编辑 / 发布 / 审核）与授权、护栏覆盖、审计日志
  - 模板广场：二期，置灰占位
- 面包屑从页面所属的一级目录开始：Agent 页面「Agent 目录 > Agent 名称 > 步骤」，资产中心「资产中心 > 二级目录」，其余只显示页面名。
- 演示剧本与自由浏览分开：从 Agent 目录点进任何 Agent 是自由浏览（剧本暂停，不显示浮层、不锁定按钮）；
  只有点工作台的「开始剧本 / 继续剧本」才进入剧本模式。退出剧本：浮层里的「退出剧本」，或右上角「重置演示」后从 Agent 目录进入。
- 生产骨架 ①–⑩ 不单独成轴，落在对应环节里：构建 ①；评测 ②；发布与实验 ③④⑤；观测 ⑥⑧；
  监控与成本 ⑦⑩；治理 ⑨⑩；资产中心承接 ① 的知识 / 工具版本。
- 笔试作答的 6 大模块与导航的对应：模块一构建 → Agent「构建」+ 资产中心；模块二评测 → Agent「评测」+ 资产中心 · 评测集；
  模块三发布与实验 → Agent「发布与实验」；模块四运行时 → Agent「设置」+ 监控与成本；模块五观测与优化 → Agent「观测」；
  模块六安全合规成本 → Agent「设置」（护栏）+ 治理 + 监控与成本。

## 原型的四个主角（外部产品普遍薄弱的差异化能力，在产品流程里做扎实，不做单独的视觉标记）
1. 强制上线门槛：候选版本可以先评测，门槛不通过时发布按钮禁用
2. 流量灰度 + 业务指标 AB：平台分流、会话粘性、版本号写入埋点
3. 含知识的版本快照 + 分钟级回退：回退 = 把线上指向切换到旧版本
4. 与公司内部基建打通：实验平台、内容安全、标注平台、监控

## 核心对象
Agent 版本：不可修改的快照，包含主模型与备用模型、最大思考次数、Prompt、编排、工具（带版本，每个工具一个版本）、知识版本与检索设置、数据库、记忆、对话体验、输出格式。运行策略、护栏按 Agent 生效，不随版本切换。
工作草稿：构建页的修改自动保存为草稿，可以直接调试；「保存为候选版本」才写入快照。
「线上指向」：生产环境当前指向哪个版本。发布和回退都是改变指向。

## 示例 Agent（mock 数据）
三个剧本 Agent 的名称是业务方定义的完整名称，所有页面和文档统一写作「社区穿搭灵感 Agent」「生态守护 Agent」「电商售后答疑 Agent」。
- 通用示例｜内部制度问答助手：在线、多轮、低风险；等级：生产；线上指向 v3
- A｜社区穿搭灵感 Agent：在线、高并发；指标：采纳率、点击率、7 日留存、P95 延迟；线上 v12，灰度 v13（10%）
- B｜生态守护 Agent：批量；指标：分类别召回率和误判率、红线样本通过率、申诉改判率；线上 v7（政策库 2026-09 版），v8 待发布
- C｜电商售后答疑 Agent：多轮会话；指标：解决率、满意度、转人工率、过期知识命中数；线上 v21（售后知识 v34）
每个 Agent 都有：负责人、所属团队、等级（原型 / 生产）、本月成本。

## 标记规则
- Demo 按题目要求走通 MVP 核心流程：生产骨架是产品设计时考虑的点，融入页面，不在界面上展示骨架编号、「生产骨架」区块或「主角」标签，也不提供「只看基础能力 / 显示生产骨架」切换
- 每个功能显示「MVP」或「二期」徽章；二期功能置灰占位，不实现交互
- 顶栏只保留面包屑和「重置演示」；不做团队切换
- 演示剧本是辅助入口：放在工作台 Agent 目录下方；右下角浮层 ✕ 只收起不退出，只在当前步骤所在页面自动展开
- 三条剧本结构一致：都从新建候选版本开始，走完「构建 → 调试 → 评测 → 发布 → 上线后」，让评审体验完整的 MVP 流程

## 风格规范

### A. 设计规范

为「Agent 基建平台」设计一套明亮、专业、亲和的 SaaS 工具产品界面。
目标用户是公司内各业务团队的产品、运营、算法和开发人员。
所有文案、图像和业务流程都使用本产品的实际内容。

1. 视觉基调：浅灰白页面背景、白色内容卡片、深灰正文；以珊瑚红作为唯一主要操作色。
   暖橙、靛蓝、翠绿仅用于区分功能类别、步骤或状态，避免大面积同时使用多种强调色。
2. 字体层级：中文优先 Noto Sans SC，英文和数字用 Inter。页面标题粗体、字距紧凑；
   正文清晰易读；辅助说明使用较浅的灰色。每个主要区块采用「小标签、明确标题、一句解释、具体内容」的信息层级。
3. 页面布局：内容居中并限制最大宽度，保留充足留白。
   平台首页（可选）采用左侧价值主张与行动按钮、右侧真实产品界面预览的首屏；
   后续用价值卡片、流程步骤、功能展示和底部行动区介绍产品。
   工作台页面采用清晰的步骤导航，桌面端优先使用主操作区与右侧实时预览或辅助信息区的双栏布局。
4. 组件语言：卡片使用白底、细灰边框、轻阴影和柔和圆角；输入框、选项卡和标签保持统一圆角与间距。
   主按钮使用珊瑚红实底，次按钮使用白底描边。选中状态必须同时通过边框、背景和文字体现，不能只依赖颜色。
5. 交互反馈：为加载、空状态、错误、成功及不可操作状态设计明确反馈。
   动画保持轻量，以淡入、轻微位移和悬停阴影为主，不妨碍阅读或操作。
6. 响应式：宽屏可用双栏和卡片网格；窄屏改为单列，导航折叠，按钮与表单保持易点击、易阅读。
   特别检查预览对比区（版本对比、AB 报告、diff），避免固定多列造成横向溢出。
7. 内容要求：使用本产品真实的功能名称、用户任务和示例数据；按钮文案直接说明动作
   （如「运行评测」「回退到 v12」），避免空泛的营销术语。优先展示真实界面或可信的界面示意图。

### B. 补充约束

B1 设计变量（所有页面只能引用这些变量）
- 页面背景 #F7F7F8；卡片 #FFFFFF；边框 #E6E7EB
- 文字：正文 #1F2329；次要 #4E5969；辅助说明 #646A73；占位和禁用 #A8ADB5
- 珊瑚红（品牌色）#F25C54：选中边框、焦点环、图标、浅底 #FEEFEE
- 主按钮底色 #D63B32（珊瑚红加深，白字对比度 4.6:1，达到 WCAG AA），悬停 #C2332B
- 暖橙：色块和圆点 #F59A23，文字 #B25E00，浅底 #FFF4E5
- 靛蓝：#4F5BD5，浅底 #EEF0FC
- 翠绿：色块和圆点 #1AAE6F，文字 #0F7B4E，浅底 #E8F7F0
- 错误：#B42318，浅底 #FEF3F2；错误提示必须同时带图标和文字，以便和主按钮的红色区分
- 字体：Noto Sans SC + Inter；等宽字体 JetBrains Mono（用于 Prompt、代码、Trace ID、版本 diff）
- 字号：页面标题 24/32 粗体、字距 -0.02em；区块标题 18/26 半粗；正文 14/22；辅助 12/18；
  数字使用等宽数字（tabular-nums）
- 间距：4 / 8 / 12 / 16 / 24 / 32 / 48
- 圆角：卡片 12；输入框、按钮、标签 8；徽章 6
- 阴影：卡片 0 1px 2px rgba(16,24,40,.06)；悬停 0 4px 12px rgba(16,24,40,.08)
- 布局：内容最大宽度 1440；左侧导航宽 224，可折叠到 64；右侧预览区宽 400–480
- 断点：≥1280 双栏；768–1279 右侧区收为抽屉；<768 单列、导航折叠
- 动效：150–200ms ease-out，位移不超过 4px；系统开启「减少动态效果」时关闭动画

B2 状态语义（全站统一，不能混用）
- 线上 / 通过：翠绿
- 灰度中 / 进行中：靛蓝
- 待审批 / 警告：暖橙
- 阻断 / 失败 / 错误：错误红 + 图标
- 草稿：灰色
- 二期：灰色虚线边框，整块置灰且不可点击，悬停提示「二期建设」

B3 数据类组件
- 表格：行高 48，表头浅灰底，数字右对齐，长文本截断、悬停显示全文
- 指标变化：**颜色表示好坏，不表示涨跌**。延迟上升是坏事，用错误红；采纳率上升是好事，用翠绿；
  同时显示 ↑↓ 箭头和数值
- 图表：旧版本用灰色，新版本用靛蓝，门槛线用暖橙虚线；必须有图例和数据标签
- 版本 diff：新增行翠绿浅底，删除行错误红浅底，使用等宽字体
- Trace 树：缩进表示层级，每一步带耗时条；异常步骤显示错误图标

B4 本原型专属标记
- 不显示骨架编号徽章和「差异化 / 主角」标签（见「标记规则」）
- MVP 徽章：描边样式；二期徽章：灰色虚线
- 「演示数据」：页面右上角浅灰小标签
- 「已接入公司 XX 平台」：辅助说明文字 + 链接图标

B5 操作层级
- 每个区域最多一个珊瑚红主按钮
- 回退、下线、暂停这类影响线上的操作：次按钮样式 + 页面内二次确认（说明影响范围），
  不用浏览器弹窗，也不用红色实底
- 不可点击的按钮必须说明原因，比如「评测门槛未通过」

B6 图标与文案
- 图标统一使用 Lucide，线宽 1.5，尺寸 16 / 20
- 界面语言为中文；Agent、Prompt、Trace、bad case、AB 等术语保留英文
- 时间格式 2026-09-28 16:13；百分比保留一位小数；版本号写作 v12
- 只做浅色模式

## 技术约束（只做前端）
- 纯静态前端：Vite + React + Tailwind（或单文件 HTML）。
  不使用 Next.js 的 API 路由、Server Actions 等服务端功能；不写任何后端代码；不使用数据库
- 不调用任何真实的模型 API 或外部接口。调试台输出、自然语言生成配置、运行评测、批量任务的结果，
  都从 mock 数据里读取预设结果，并配 0.5–1.5 秒的模拟加载
- 「发布」「回退」「放量」「审批」等操作只改变前端状态，页面上显示相应的变化
- 「已接入公司 XX 平台」「版本号已写入埋点」只是界面上的说明文字，不做真实对接
- 上传文件：只在前端读取文件名和行数，然后展示预设结果；下载：导出预设的 CSV
- 状态保存在前端内存里；可以用 localStorage 保留演示进度（读写失败时不影响使用）；
  全局提供「重置演示」按钮，一键恢复初始数据
- 所有颜色、字号、间距只能引用 B1 的设计变量，不许写死数值
- 字体通过 Google Fonts 引入；图标使用 Lucide
- mock 数据放在 `src/data`：`base/` 按功能拆分，`scenarios/` 按演示剧本拆分，统一从 `src/data/index.ts` 导出；页面、组件和逻辑层只从这个入口引用
- 构建产物是静态文件，可以直接部署到静态托管打开，不需要启动服务端

## 部署约束（保证随时能打包成单个 HTML）
- 使用 vite-plugin-singlefile，`npm run build` 输出一个自包含的 dist/index.html（JS、CSS 全部内联）
- Vite 配置 base: './'，所有资源用相对路径
- 路由用 HashRouter（网址形如 #/agents/a），或者直接用页面状态切换；不用 BrowserRouter
- 不用动态 import 和代码拆分；所有依赖打包进来，运行时不从外部 CDN 加载脚本
- 图片优先用内联 SVG 或小图，避免单文件体积过大
- 字体：Google Fonts 加载失败时回退到系统字体（PingFang SC、Microsoft YaHei、sans-serif）
- 本地存储：所有读写都包在 try/catch 里，不可用时页面照常工作

## 代码组织
- 按功能分文件夹：`src/features/<功能>/` 放该功能的页面、专用组件和专用样式
- 跨页面复用的组件和样式放 `src/shared/`：设计变量、基础样式、按钮、徽章、能力卡片等
- 与界面无关的状态、规则和取数放 `src/core/`：`store/` 演示状态与操作，`rules/` 版本、门槛、生命周期、演示时钟，`data-access/` 统一取数（演示剧本在这里替换数据）
- mock 数据放 `src/data/`（见技术约束）
- 依赖方向：features → shared → core → data → types，只允许从左往右引用；功能之间尽量不互相引用，例外是公共外壳 `features/shell` 和剧本锁定 `features/playbook/playbooks`
- 改完运行 `npm run smoke`（三条剧本 + 回归检查）；涉及样式时运行 `npm run snapshot:compare`，与改动前的基准截图比对
